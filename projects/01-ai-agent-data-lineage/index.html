01 · Stages

Understand the 8 stages

The path of an HR data point, from the source to the answer in the chat. Each stage is a column of the map.

1

Source systems

Where the data is born: company systems and spreadsheets.

payroll, recruiting, engagement survey
2

ETL

Scripts that read, clean, standardize and consolidate. ETL = extract, transform, load.

etl_headcount.py, etl_exits.py
3

Bronze

Consolidated data, still nominal. Internal use, never goes to the agent.

.parquet files with a person key
4

Aggregation

Sums by company and month, applies business rules and k-anonymity, removes personal data.

build_gold_*.py scripts
5

Gold

Ready-to-use summary: one spreadsheet per topic and cut, with nobody identifiable.

anonymized .xlsx files
6

Knowledge folder

A cloud folder that serves as the agent's knowledge source.

indexing takes minutes
7

Agent

Reads only the Gold files, follows explicit instructions and answers.

language model on a low-code platform
8

Channel

Where people talk to the agent, in natural language.

chat app with corporate sign-in

Bronze and Gold in one sentence

Bronze · full data

The stock

The consolidated base as it is: one row per person, with identification. It serves the calculations and stays out of the agent's reach.

  • Contains person key, company, area
  • .parquet format, full history
  • Never connected to the agent
Gold · ready data

The showcase

Numbers already grouped, for example headcount by department and month. It is the only layer the agent sees.

  • Group totals only
  • .xlsx format, because the knowledge source does not read .parquet
  • Standard name: Topic - Cut.xlsx

Privacy rule: k-anonymity

Protecting people

A small group does not show

A number only enters the Gold if the group has at least k people. That way nobody is identified by exclusion: if only 2 people in an area have a given characteristic, the value is suppressed. Try the control on the right.

03 · Attention

Attention points

What usually goes wrong or needs care when changing this flow.

Critical

Bronze holds a person key. No file at that level may be connected to the agent.

Critical

The knowledge source only reads .xlsx. A .parquet file in the folder is ignored.

Attention

A new or changed file takes a few minutes to be indexed. Testing earlier gives a false negative.

Attention

Changing the knowledge source means remove, publish, wait, re-add and publish again.

Attention

Joining lists by key requires normalizing both sides (for example, restoring leading zeros). Otherwise the join fails silently.

Attention

A total published next to a suppressed cut reveals the hidden cell by subtraction.

OK

k-anonymity applied to the cuts: groups below k are suppressed.

OK

The master file defines which file to use as the fallback. The agent does not choose on its own.

Controlled complexity

  • Each Gold depends on 1 to 4 sources
  • Business rules applied once, in the script
  • Bridges between bases, such as ID → person key

Optimization gain

  • Questions answered in seconds
  • Monthly close stops being manual
  • A single source of standardized summaries

Flow security

  • Personal data out of the agent's reach
  • Small groups suppressed
  • An indicator without data is declared "n/a", never estimated
